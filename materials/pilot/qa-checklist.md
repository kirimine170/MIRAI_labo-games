# 教材QAチェックリスト

## A．版と欠陥の準備

- [ ] 完成版の元コミットと版IDを記録した．
- [ ] 1課題へ欠陥を一つだけ注入した．
- [ ] 完成版と欠陥版の差分が，注入仕様と一致する．
- [ ] 意図した症状が3回中3回再現する．
- [ ] 構文エラー，起動不能，欠損アセットがない．
- [ ] 完成版の退避コピーがあり，生徒の編集先と分かれている．
- [ ] 問題なし版が，名前や更新日時だけで識別されない．

## B．ゲーム品質

- [ ] 説明後，5分以内に基本操作を理解できる．
- [ ] 操作へ即時の数値または見た目の反応がある．ただし `RR-F01` の意図した不足を除く．
- [ ] 成功と失敗の条件が区別できる．
- [ ] 終了後に結果が勝手に変わらない．ただし `SW-S01` の意図した症状を除く．
- [ ] 緑の旗で初期状態から再挑戦できる．
- [ ] 本家Scratchで動作する．
- [ ] 対象端末で文字，画像，クリック範囲が確認できる．

## C．教材品質

- [ ] 生徒用仕様に，観察可能な期待動作が書かれている．
- [ ] 生徒用資料から修正箇所や答えが漏れていない．
- [ ] 生徒用欠陥版は`build-student-defect.sh`で生成し，patchと教師用manifestを配布物から除外した．
- [ ] 観察事実と原因推測を分ける欄がある．
- [ ] 他者が追試できる再現手順を記録できる．
- [ ] 仮説を実行前に書ける．
- [ ] 正常系，境界値，回帰テストを記録できる．
- [ ] 変更しない判断を提出できる．
- [ ] 想定外の別解を判定する共通基準がある．
- [ ] ヒントが観察，追跡，絞り込み，修正の順に段階化されている．
- [ ] ルーブリックの各観点に証拠を対応させられる．

## D．45分進行

- [ ] 0〜5分で目的と仕様を確認する．
- [ ] 5〜15分で観察と再現を行う．
- [ ] 15〜22分でコード追跡と仮説を行う．
- [ ] 22〜32分で修正または非変更判断を行う．
- [ ] 32〜38分で検証を行う．
- [ ] 38〜45分で説明と終了チケットを行う．
- [ ] 配布，ログイン，環境準備を授業前に完了した．

## E．LLMと公平性

- [ ] LLM利用の可否と範囲を授業前に示した．
- [ ] LLMを使わない学習者へ同等の段階ヒントがある．
- [ ] 利用目的，提案要約，採否，独立検証を記録できる．
- [ ] LLMの回答自体ではなく，学習者の説明とテストを評価する．
- [ ] チャット全文の提出を必須にしていない．

## F．未成年者の安全とプライバシー

- [ ] 氏名ではなく無作為なセッションIDを使う．
- [ ] 標準ログは課題ID，版ID，試行，ヒント，変更要約，評価に限定する．
- [ ] 公開リポジトリへ個人データを保存しない．
- [ ] 氏名との対応表が必要な場合，教材データと分離し，アクセスを制限した．
- [ ] 保存期限，削除方法，担当者を決めた．
- [ ] 映像，音声，詳細ログを研究収集する場合，必要な説明，同意，機関手続きを確認した．
- [ ] LLMへ個人情報や他の児童生徒の情報を入力しないよう説明した．
- [ ] 参加やデータ提供を断っても，授業上の不利益がない代替を用意した．

## G．授業後

- [ ] 技術トラブルと学習上の困難を分けて記録した．
- [ ] 想定外の別解を，不正解とせず受入基準で再評価した．
- [ ] 新たに見つかった不具合を，再現手順と環境付きで記録した．
- [ ] ヒント到達段階と所要時間を匿名で集計した．
- [ ] 45分以内に説明まで到達できなかった原因を記録した．
- [ ] 教材の改善と，教育効果の主張を分けた．
