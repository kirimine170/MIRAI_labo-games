# アーキテクチャ

## 目的

このリポジトリの責務は，Scratchで実行できるゲームと，それをデバッグ学習に利用する教材定義を，バージョン管理可能な形で保持することです．`.sb3`は入力ではなく生成物です．

## 現在の実装境界

- `games/<slug>/`は，1つのgoboscriptプロジェクトです．現在の2ゲームは独立したソースとアセットを持ち，共通エンジンはまだありません．
- リポジトリ直下の`main.gs`，`stage.gs`，`assets/`は，コンパイラの最小スモークテストです．教材カタログへは登録しません．
- `tools/projects.txt`はビルド対象の正本です．ディレクトリを追加しただけではCI対象になりません．
- `tools/goboscript-version.env`はコンパイラ，Rust toolchain，標準ライブラリの固定値の正本です．

## 1ゲームの必須構造

```text
games/<slug>/
├── goboscript.toml    標準ライブラリ版を固定
├── stage.gs          ScratchのStage
├── main.gs           主要スプライト
├── *.gs              UIやその他のスプライト
└── assets/           ソースから参照するアセット
```

ファイル名はScratch内のスプライト名に対応します．`stage.gs`は特別で，Stageを定義します．

## 再現性

2026年8月14日時点のビルド基準は次の組合せです．

| 要素 | 固定値 | 理由 |
| --- | --- | --- |
| goboscript | commit `0c5270be8aaa4c21fa61f8c06f11ea40356c1074`（開発中3.3.0） | 公開済みv3.2.1は現行ソースの負数初期値を解釈できない |
| Rust | `nightly-2026-08-12` | 固定したgoboscriptがnightly機能を使用する |
| goboscript std | `2.1.0` | 未指定時の日次更新を避ける |

固定したgoboscriptはタグ付き安定版ではありません．これは既存ゲームのロジックを変更せずにコンパイルできることを優先した暂定選択です．次のgoboscriptリリース時に再評価します．

## データの境界

- GitHubに置くもの：公開可能なコード，アセット，仕様，教材，匿名化後のテストデータ．
- 制限付き保管先に置くもの：同意書，氏名，映像，音声，個人とセッションの対応表，未匿名化の操作ログ．
- 運用表に置くもの：担当，期限，進捗，外部公開URL．ゲーム仕様を運用表とGitHubの両方で手修正しません．

## CIが保証する範囲

CIは次を検査します．

1. 各プロジェクトの必須ファイルと標準ライブラリ固定値がある．
2. `.sb3`がGitに追跡されていない．
3. 固定コンパイラで全プロジェクトをコンパイルできる．
4. 生成された`.sb3`をZIPコンテナとして読み取れる．

CIは，Scratchでの実行時振る舞い，本家ScratchとTurboWarpの差，ゲームバランス，アクセシビリティ，欠陥の教育的妥当性，資料の授業可能性までは保証しません．それらはレビューと手動プレイテストで判定します．
